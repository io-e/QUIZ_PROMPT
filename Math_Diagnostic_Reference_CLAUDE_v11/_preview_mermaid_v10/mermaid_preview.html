2. 3. Input validation flow

flowchart TD
    Start(["Request"]) --> L{"LEVEL given
and valid?"}
    L -- no --> Ask1["STOP and ask"]
    L -- yes --> C{"Combination
allowed?"}
    C -- no --> Ask1
    C -- yes --> Sub{"SUBJECT codes
belong to LEVEL?"}
    Sub -- no --> Ask2["List valid codes and ask"]
    Sub -- yes --> Tc{"TARGET_CODES exist
in reference?"}
    Tc -- no --> Ask3["Propose closest codes and ask"]
    Tc -- yes --> Time{"Sum of item times
at most 90% of DURATION?"}
    Time -- no --> Ask4["Propose fewer items and ask"]
    Time -- yes --> Go(["Generate"])

4. 6. Evidence states

stateDiagram-v2
    [*] --> SUSPECTED: wrong MCQ option, signature unique to one error
    [*] --> UNDETERMINED: shared signature, no visible step, or no match
    SUSPECTED --> CONFIRMED: matching reason, or written work, or student explanation, or discriminating follow-up item
    UNDETERMINED --> CONFIRMED: separating follow-up item
    CONFIRMED --> [*]: supports a misconception

6. 11.3 Marking and coding

flowchart TD
    A["Answer"] --> B{"MCQ?"}
    B -- yes --> C{"Option"}
    C -- key --> OK["Point"]
    C -- "Je ne sais pas" --> N["No point, no error code"]
    C -- distractor --> D["Log its code (T6)
evidence SUSPECTED"]
    B -- no --> E{"Step written?"}
    E -- "yes, matches a rubric code" --> F["Log the code
evidence CONFIRMED"]
    E -- "no visible step" --> G["Candidate codes only
evidence UNDETERMINED"]
